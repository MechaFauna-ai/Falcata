# Falcata 1.2.0

Unreleased.

## Features and performance

- **Complete bounded device trees by default** (#164). Quantized, scalar (one output per tree), numerical (no
  categorical features), single-GPU CUDA trees without per-node feature masks (`feature_fraction_bynode` 1.0) whose
  depth bound holds (positive `max_depth <= 10`, 12 since #165, and `2^max_depth <= num_leaves + 1`) now grow entirely
  on the device:
  every level's select, apply and search plus the final apply, with one growth readback and no host growth tail
  (`cuda_plan` key `device_tree`, now default on). Measured on an RTX 5090 against `device_tree:off` (the 1.1 default
  flow), same binary: covtype deep 1.068x, higgs deep 1.025x, Numerai deep 1.007x, Numerai with missing values
  1.002x, four generated shapes 1.008-1.042x; geometric mean 1.025x over the eight cells. Model outputs are unchanged
  (bit-identical models). Other shapes keep the `device_levels` prefix and the host flow. Opt out with
  `cuda_plan="auto,device_tree:off"` (the 1.1 default prefix flow) or `cuda_plan="auto,device_levels:off"` (the host
  flow). The 1.1 opt-in spelling `auto,device_levels:off,device_tree:on` now selects the host flow; use `auto` (or
  `auto,device_tree:on`).
- **Leaner complete device trees** (#167). The device tree's lean tree end (no split-batch readback or host leaf
  bookkeeping, the final level's inline leaf map) now covers every objective boosted on the device, weighted and
  row-bagged trees of two or more levels (`cuda_plan` key `device_tree_lean_end`); graph keys that keep changing
  (feature-sampled wide data) update a cached graph in place instead of instantiating a new one
  (`device_level_graph_update`); and every tree starts with the same index-buffer roles, so odd-depth trees no longer
  capture each graph layout twice (`index_parity_canonical`). All default on. Same binary, each key off vs on, RTX
  5090: covtype deep 1.016x and higgs deep 1.013x (lean end), Numerai with missing values 1.007x (graph update); 1.019x
  / 1.013x / 1.009x against #164. Model outputs are unchanged (bit-identical models).
- **Device tree levels sized to their live pairs** (#168). A complete device tree's level fix/subtract and bit-change
  copy no longer launch one block row per pair of the level's worst case (2^level) where that would exceed
  `device_tree_live_grid` blocks per SM (`cuda_plan` key, default 32; 0 restores the worst-case launch): a bounded
  grid strides over the live pairs on the device. This matters on wide histograms. Same plan against master, RTX 5090:
  epsilon-fixedpoint 1.040x, epsilon-sampled 1.074x, fraud deep 1.016x; covtype deep, higgs and year unchanged
  (1.000-1.002x). With the depth-12 bound of #165, epsilon at depth 11 goes from 0.838x to 1.141x against the prefix
  flow (#165's measurement on master; 0.838x is the depth-12 bound without this change). Model outputs are unchanged (bit-identical models).
- **Complete device trees up to `max_depth` 12** (#165). The complete device tree's depth bound rises from 10 to 12
  (`2^max_depth <= num_leaves + 1` unchanged): the whole tree's select holds 2048 candidates, its per-level scratch
  is presized for the 2^(max_depth-2) pairs it actually searches with the quantized bit-change scratch at int32, and
  a shape whose presized scratch would take more than half of the free device memory keeps the prefix flow
  (`FALCATA_DEBUG=diag` prints the estimate). Default plan against master (which grows these shapes with the
  prefix flow), RTX 5090: epsilon at depth 11 1.141x, covtype 1.067x / 1.073x and higgs 1.068x / 1.095x at depth
  11 / 12; shapes already within the old bound unchanged (covtype deep 0.999x, epsilon fixedpoint 1.000x). Model
  outputs are unchanged (bit-identical models).
- **Complete device trees at any depth, in pair chunks where memory is short** (#181). The complete device tree has no
  depth limit any more (any positive `max_depth` with `2^max_depth <= num_leaves + 1`): levels wider than 2048
  splits select over global scratch with the same sort network and tie order, and the growth journal tags each split
  with its level. A shape whose per-level search scratch would take more than half of the free device memory no
  longer falls back to the prefix flow: the wider levels run their fix/subtract and split search in pair chunks
  (`FALCATA_DEBUG=diag` prints the plan, `... searched pairs, C chunks of P pairs`); where not even one pair per
  chunk fits, the host level loop grows the trees (reason `scratch_too_large`). The reasons `depth_gt_12` and `memory_gate` are gone. Default plan
  against master, RTX 5090, 1000 rounds: covtype 8191/13 1.137x, higgs 16383/14 1.207x and 131071/17 1.194x (from the
  prefix flow); epsilon 2048/11 under a 2 GB memory cap 1.142x (pair chunks instead of the prefix); the complete tree's
  select also writes its descriptors in wide stores, so shapes already on it gain too (higgs 4096/12 1.127x, covtype
  2048/11 1.061x, covtype deep 1.040x, epsilon fixedpoint 0.998x). Model outputs are unchanged (bit-identical models).
- **Complete device trees with per-node feature sampling** (#171). Trees with `feature_fraction_bynode < 1` (without
  interaction constraints) now grow as complete device trees too: each node's keyed feature sample, its mask and its
  task list are drawn by a device kernel beside each level's histogram construct, inside the tree's captured graph,
  instead of on the host per level with two uploads (`cuda_plan` key `device_bynode_masks`, default on; off restores
  the host level loop). The kernel reproduces the host's keyed draw exactly (the same generator, the same
  `Random::Sample` branch, the same task lists), so models are unchanged (bit-identical models). Measured on an RTX
  5090 against master, default plan, 1000 rounds: covtype small (7 classes, 128 leaves / depth 7) with
  `feature_fraction_bynode` 0.5 1.322x, fraud deep (1024 / 10) with 0.5 1.206x; covtype deep without per-node
  sampling 1.003x and random forest (forest slots, unchanged route) 1.005x; epsilon (512 / 9, `feature_fraction` 0.5) with 0.5
  1.485x.
- **Categorical CUDA trees no longer reallocate per split** (#170). Each categorical split grew the tree's device
  bitsets by a fresh allocation, two copies and a free (and a free synchronizes the device): about 37 allocations and
  37 frees per tree on a 32-leaf multiclass categorical cell. The categorical split record now lives in buffers the
  tree learner keeps across trees, presized to the per-tree bound and grown by doubling, and each tree keeps only
  exact-size copies of what prediction reads (about 3 allocations and 4 frees per tree remain, none per split). Master
  vs this change, RTX 5090: categorical 32/5 multiclass 1.177x (0.816 -> 0.693 ms/tree), airline with three
  categorical columns, 1023 leaves/depth 10, 1.092x (49.1 -> 44.9 ms/tree); covtype deep (no categorical features)
  unchanged (1.000x). Model outputs are unchanged (bit-identical models).
- **Selective growth starts on the device** (#172). A binding leaf budget
  (`2^max_depth > num_leaves + 1`) or unlimited depth (`max_depth = -1`) trains with selective grow-then-prune growth,
  which read every level back twice. Its first K = `min(floor(log2(num_leaves)), max_depth - 1, 10)` levels (when
  K >= 2), on which it provably splits every valid leaf, now run as the graph-captured `device_levels` prefix; the
  host's selective loop
  continues from the prefix's journal (`cuda_plan` key `selective_device_prefix`, default on). Same eligibility as the
  prefix (quantized, numerical, scalar, single GPU, `feature_fraction_bynode` 1.0). Strict A/B against master
  `fe163428`, RTX 5090, 1000 rounds: binding budget 151/10 1.089x, unbounded 1024 leaves 1.064x, higgs 255/10 1.042x,
  fraud 255 unlimited 1.049x; complete-device-tree cells unchanged (covtype deep 0.997x, epsilon fixedpoint 0.999x).
  Model outputs are unchanged (bit-identical models).
- **The selective prefix is trimmed**. The device levels that start selective growth (see above) no longer record
  a device tree that selective growth never reads. The select that runs at the end of each level's best-split sync
  kernel is several microseconds shorter per level (for the plain `device_levels` prefix too). The hand-off to the host loop copies each journaled split record
  once. The partition launch takes the complete device tree's joint worker bound. No new `cuda_plan` keys (part of
  `selective_device_prefix`). Strict A/B against master `5bec2574`, RTX 5090, 1000 rounds:
  - binding budget 151/10: 1.034x;
  - unbounded 1024 leaves: 1.035x;
  - higgs 255/10: 1.027x;
  - fraud 255 unlimited: 1.025x;
  - complete-device-tree cells unchanged (covtype deep 1.002x, epsilon fixedpoint 1.001x).

  Model outputs are unchanged (bit-identical models).

- **Random-forest groups of one tree take the device flows** (#173). Under `forest_batched` a group of one tree
  (`forest_group:1`, a binary or regression forest whose automatic group size settles at one round, the last group of
  a `forest_group:N` training, every round of a binary or regression forest under fixedpoint error feedback) now trains on the booster's learner as sequential
  training does instead of as a forest slot: no other slot thread runs beside it, so it takes the complete device
  tree (with device per-node masks) and the `device_levels` and selective device prefixes (and, before #177, the
  quantized graph prefix under `graph_quant:on`). Groups of two or more trees (every multiclass round) keep slot mode (`cuda_plan` key
  `forest_single_job_device`, default on; `FALCATA_DEBUG=diag` names each group's mode). RTX 5090, master vs this
  change: rf-control (binary, depth 7, `feature_fraction_bynode` 0.5) 1.243x, without per-node sampling 1.064x;
  multiclass and non-quantized forests and gbdt unchanged (0.988-1.002x, noise). Model outputs are unchanged
  (bit-identical models).
- **Categorical CUDA trees record a level at once** (#174). The level loop read each level's categorical bitset
  lengths back and then recorded every categorical split with its own launch and two blocking copies. One kernel now
  records all of a level's categorical splits and appends their bitsets at offsets summed on the device, and the tree
  end reads the whole categorical record back with one copy (`cuda_plan` key `cat_level_record`, default on). Master vs
  this change, RTX 5090, 1000 rounds: categorical 32/5 multiclass 1.170x (0.695 -> 0.594 ms/tree), the same at 255
  leaves/depth 8 1.177x, airline with three categorical columns, 1023 leaves/depth 10, 1.058x (45.2 -> 42.7 ms/tree);
  covtype deep (no categorical features) unchanged (1.004x). Model outputs are unchanged (bit-identical models). Also
  fixes CUDA training on a categorical feature whose largest category value is a positive multiple of 32: its bitset
  was sized one word short (a largest value of 64 failed with an invalid-argument CUDA copy).

- **Why a tree is not a complete device tree, and opt-in routing keys removed** (#177). Under `FALCATA_DEBUG=diag`
  every CUDA tree the complete device tree did not grow is reported as `device_tree: fallback (<reason>)
  route=<route>`, once per route change, with a stable reason vocabulary (`selective_budget`,
  `categorical`, `monotone`, ...; listed in `docs/performance.md` and
  `include/Falcata/cuda/cuda_device_tree_reason.hpp`); it replaces the `device_tree: fallback to the prefix/host flow`
  and `device_tree: host fallback` lines. Removed, with the flows only they reached: the `cuda_plan` keys
  `batch_kernels`, `batch_apply`, `selective`, `batch_wide`, `cat_hybrid`, `apply_struct_fused`, `gap_copy_fused`
  and `graph_quant` (the opt-in quantized captured graph prefix), the `FALCATA_DEBUG` tokens `syncpairs`, `maxsplits=N`
  and `aggressive`, and the `FALCATA_SINGLE_STREAM` switch. Old plan strings that name a removed key are accepted with a
  warning and now train the default model. Default-plan model outputs are unchanged (bit-identical models).
- **Non-quantized trees grow as complete device trees; the non-quantized graph loop is removed** (#180).
  Depth-limited `quant_mode=none` trees with `max_depth <= 11` and `num_leaves <= 2047` (single GPU, scalar,
  numerical, no per-node masks), which the CUDA-graph level loop (L1.5) grew, now take the complete device tree: its
  levels construct in 64-bit fixed point and run the non-quantized fix/subtract and level find on the device's live
  pairs, the graph loop's kernels, so models are unchanged (bit-identical models) and run-to-run deterministic. The
  graph loop, its device controller and the `cuda_plan` keys `graph_loop` and `graph_det` are removed (old strings are
  accepted with a warning; `graph_loop:off`'s one-sync flow is now `device_tree:off`). Other non-quantized shapes keep
  the one-sync host flows. Strict A/B against master, RTX 5090, 1000 rounds: nonquantized control (128 / 7) 1.406x,
  fraud deep non-quantized (1024 / 10) 1.470x, higgs non-quantized (1023 / 10) 1.845x; quantized covtype deep and
  epsilon fixedpoint unchanged (0.999x each, walls overlapping).
- **Complete device trees with L1, path smoothing and two leaves; no root tail** (#182). Quantized trees with
  `lambda_l1` or `path_smooth` grow as complete device trees: the level split finder now has the per-pair search's
  L1 / smoothing instantiations (each block runs the per-pair kernel's own inner search), where these configurations
  took the host two-sync loop's per-pair search before. Quantized two-leaf trees (`num_leaves=2`, any `max_depth`) are
  the complete device tree at depth 1 (before: the per-split loop). The device tree's root tail is removed: a
  split-less level root used to be searched again with the classic per-leaf search, which since the per-tree feature
  sample is translated to bin-matrix columns finds no split either. Models are unchanged (bit-identical models).
  Non-quantized L1 / smoothing trees and stumps, and L1 / smoothing with per-node feature sampling, keep their routes
  (moving them would change their models). The `device_tree: fallback` reasons `compact_16bit`, `large_bin_layout`
  and `root_tail_parity` are removed (the first two named configurations that a feature of more than 256 bins already
  refuses). Strict A/B against master, RTX 5090, 1000 rounds: fraud deep with `lambda_l1` 2.648x, covtype small with
  `path_smooth` 3.489x, fraud medium with `num_leaves=2` 1.506x; covtype deep, epsilon fixedpoint and the unchanged
  routes 0.999x to 1.004x.

- **Categorical datasets grow as complete device trees; the per-split categorical record is removed** (#P5PR).
  Quantized, depth-limited trees with categorical features (`2^max_depth <= num_leaves + 1`, single GPU,
  scalar), which the host level loop grew with two readbacks per level, now take the complete device tree:
  its select lists each level's categorical splits, one kernel builds their bitsets and the apply's default
  directions, and the tree records the level on the device at offsets summed there (#174's level record), inside the
  tree's captured graph; the record buffers are sized for the tree's worst case before it starts, so nothing grows
  or is read back while the tree grows; categorical trees also take the lean tree end with its inline final-level
  leaf map. Models are unchanged (bit-identical models). The presized record counts as
  fixed scratch of the device tree's memory plan (#181's pair chunks: a record that leaves no room for one pair's
  search, at very high category values, keeps the host level loop with reason `scratch_too_large`); `quant_mode=none`
  keeps the host flow (reason `categorical`). The `cuda_plan` key `cat_level_record` is removed with the per-split record loop it switched back
  to (old strings are accepted with a warning); vector-leaf trees record categorical levels the same way. Strict A/B
  against master, RTX 5090, 1000 rounds: categorical 32/5 multiclass 1.138x (0.607 -> 0.533 ms/tree), the same at
  255 leaves/depth 8 1.152x, airline with three categorical columns (1023/10, kernel-bound) 0.998x; categorical
  unbounded (selective, unchanged route) 1.000x, covtype deep 0.999x and epsilon fixedpoint 0.999x (no categorical
  features).

## Documentation

- **`num_gpu` states the multi-GPU requirements**: NCCL loaded at runtime (`falcata[multigpu]`, an NCCL 2.x wheel such as `nvidia-nccl-cu13`, or a system `libnccl.so.2`; without it training falls back to one GPU), the depth-limited configuration quantized multi-GPU needs (at least `2^max_depth <= num_leaves + 1`), host-staged transport (for data that does not fit one card, not for speed) and how multi-GPU models differ from single-GPU ones. Both NCCL wheels verified with falcata 1.1.0 on 2x RTX A4000, driver 580.
