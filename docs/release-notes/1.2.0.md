# Falcata 1.2.0

Unreleased.

## Features and performance

- **A native GPU predictor** (#618). `Booster.predict()` scores dense rows with Falcata's own CUDA predictor, with no
  cuML, Treelite or nvforest: numpy, CuPy, PyTorch or any `__cuda_array_interface__` input (device arrays stay on the
  device and come back in the same library), 64-bit row counts in bounded device chunks, every model kind (numerical
  and categorical splits, missing values, linear trees, vector leaves, multiclass, iteration slices), normal and raw
  predictions, leaf indices and feature contributions (TreeSHAP). Raw scores, leaf indices and contributions are
  bit-identical to the CPU predictor's, and normal predictions are converted from the raw scores by the same code.
  `predict(device=None | "cpu" | "cuda")` chooses the predictor by documented rules before anything runs: a device
  array goes to the GPU; a `device_type="cuda"` model's numpy array goes to the GPU only when a cost estimate expects
  the GPU to be clearly faster and the call's device buffers are small (see below); a failure on the GPU is raised,
  never retried on the CPU. `Booster.cuda_predict_stats` reports the device memory of the last CUDA prediction. The FIL route is
  now the opt-in `use_fil=True` (removed in #619).
- **Native GPU predictor: a fast default mode, a deterministic mode, and `predict_many`** (#620). On the GPU,
  `Booster.predict()` now adds each output's leaf values in one fixed pairwise order by default (groups of 8 iterations
  in tree order, then a binary tree over the groups), which spreads a row's trees over the device; the order depends
  only on the model and the iteration range, so a row gets the same bits in any batch, call and GPU, and differs from
  the CPU predictor's in-order sum by rounding only (at most 1.2e-13 on the benchmark matrix). Leaf indices and feature
  contributions stay bit-identical. `predict(..., deterministic=True)` (the C API's new `deterministic` argument of
  `FLC_BoosterPredictForMatCUDA`) keeps the in-order sum, bit-identical to the CPU predictor. `falcata.predict_many` /
  `FLC_BoostersPredictForMatCUDA` predict many (booster, input, iteration range) jobs in a few launches, each with
  exactly its own `predict` result. RTX 5090, 113 cells (16 synthetic shapes and 11 real models of a downstream run, 1
  to 10M rows), device input, against nvforest 26.10 in its default configuration: the default mode is faster than FIL's
  fp32 routing in 113 of 113 cells (min 1.03x, median 2.84x) and than its exact fp64 routing in 113 of 113 (min 1.32x,
  median 4.80x); on 508 real models of 500 rows each, one `predict` per model is 16.4x FIL fp32's loop and
  `predict_many` 16.7x. The deterministic mode is bit-identical to the CPU predictor in all 113 cells. Details in
  docs/performance.md section 8.
- **`predict(device=None)` on numpy arrays: the GPU only where it wins.** The first 1.2.0 candidate sent every numpy
  array of a `device_type="cuda"` model to the GPU, which was slower than 1.1.0's CPU prediction on shallow models and
  on wide rows (+34% to +171% on four cells of the 1.2.0 speed matrix) and held up to 1 GB more device memory: the
  first CUDA prediction of a process loads the predictor's kernels (44-87 ms), and wide rows cost as much to copy as
  the CPU needs to predict them. `device=None` now estimates both predictors' time (rows, split nodes per row, columns,
  CPU threads, copies, whether the kernels are loaded and the model packed) and uses the GPU only when it is faster by
  a 1.3x margin and the call's buffers are at most 256 MiB and an eighth of the free device memory; it then sums in
  tree order, so `device=None` returns the CPU predictor's result bit for bit either way (before, the automatic GPU
  predictions differed in the last bits). The estimate's constants were measured on one RTX 5090 with a 16-core CPU.
  `device="cuda"` and `device="cpu"` are unchanged. New C API `FLC_BoosterCUDAPredictCostInputs` reports what the
  estimate reads. Details in docs/performance.md section 8.
- **The FIL predict path is removed** (#619). GPU prediction needs no cuML install any more, and an installed cuML is no
  longer picked up: `predict(use_fil=...)` is a `TypeError` that names the replacement (`device=`), and
  `FALCATA_FIL` / `FALCATA_FIL_PRECISION` have no effect. FIL's per-slice model cache and its 2**29-cell host slabs
  (a workaround for its 32-bit offsets) are gone with it.

- **Complete bounded device trees by default** (#164). Quantized, scalar (one output per tree), numerical (no
  categorical features), single-GPU CUDA trees without per-node feature masks (`feature_fraction_bynode` 1.0) whose
  depth bound holds (positive `max_depth <= 10`, 12 since #165, and `2^max_depth <= num_leaves + 1`) now grow entirely
  on the device:
  every level's select, apply and search plus the final apply, with one growth readback and no host growth tail
  (`cuda_plan` key `device_tree`, now default on). Measured on an RTX 5090 against `device_tree:off` (the 1.1 default
  flow), same binary: covtype deep 1.068x, higgs deep 1.025x, Numerai deep 1.007x, Numerai with missing values
  1.002x, four generated shapes 1.008-1.042x; geometric mean 1.025x over the eight cells. Model outputs are unchanged
  (bit-identical models). Other shapes keep the `device_levels` prefix and the host flow. Opt out with
  `cuda_plan="auto,device_tree:off"` (the 1.1 default prefix flow) or `cuda_plan="auto,device_levels:off"` (the host
  flow). The 1.1 opt-in spelling `auto,device_levels:off,device_tree:on` now selects the host flow; use `auto` (or
  `auto,device_tree:on`).
- **Leaner complete device trees** (#167). The device tree's lean tree end (no split-batch readback or host leaf
  bookkeeping, the final level's inline leaf map) now covers every objective boosted on the device, weighted and
  row-bagged trees of two or more levels (`cuda_plan` key `device_tree_lean_end`); graph keys that keep changing
  (feature-sampled wide data) update a cached graph in place instead of instantiating a new one
  (`device_level_graph_update`); and every tree starts with the same index-buffer roles, so odd-depth trees no longer
  capture each graph layout twice (`index_parity_canonical`). All default on. Same binary, each key off vs on, RTX
  5090: covtype deep 1.016x and higgs deep 1.013x (lean end), Numerai with missing values 1.007x (graph update); 1.019x
  / 1.013x / 1.009x against #164. Model outputs are unchanged (bit-identical models).
- **Device tree levels sized to their live pairs** (#168). A complete device tree's level fix/subtract and bit-change
  copy no longer launch one block row per pair of the level's worst case (2^level) where that would exceed
  `device_tree_live_grid` blocks per SM (`cuda_plan` key, default 32; 0 restores the worst-case launch): a bounded
  grid strides over the live pairs on the device. This matters on wide histograms. Same plan against master, RTX 5090:
  epsilon-fixedpoint 1.040x, epsilon-sampled 1.074x, fraud deep 1.016x; covtype deep, higgs and year unchanged
  (1.000-1.002x). With the depth-12 bound of #165, epsilon at depth 11 goes from 0.838x to 1.141x against the prefix
  flow (#165's measurement on master; 0.838x is the depth-12 bound without this change). Model outputs are unchanged (bit-identical models).
- **Complete device trees up to `max_depth` 12** (#165). The complete device tree's depth bound rises from 10 to 12
  (`2^max_depth <= num_leaves + 1` unchanged): the whole tree's select holds 2048 candidates, its per-level scratch
  is presized for the 2^(max_depth-2) pairs it actually searches with the quantized bit-change scratch at int32, and
  a shape whose presized scratch would take more than half of the free device memory keeps the prefix flow
  (`FALCATA_DEBUG=diag` prints the estimate). Default plan against master (which grows these shapes with the
  prefix flow), RTX 5090: epsilon at depth 11 1.141x, covtype 1.067x / 1.073x and higgs 1.068x / 1.095x at depth
  11 / 12; shapes already within the old bound unchanged (covtype deep 0.999x, epsilon fixedpoint 1.000x). Model
  outputs are unchanged (bit-identical models).
- **Complete device trees at any depth, in pair chunks where memory is short** (#181). The complete device tree has no
  depth limit any more (any positive `max_depth` with `2^max_depth <= num_leaves + 1`): levels wider than 2048
  splits select over global scratch with the same sort network and tie order, and the growth journal tags each split
  with its level. A shape whose per-level search scratch would take more than half of the free device memory no
  longer falls back to the prefix flow: the wider levels run their fix/subtract and split search in pair chunks
  (`FALCATA_DEBUG=diag` prints the plan, `... searched pairs, C chunks of P pairs`); where not even one pair per
  chunk fits, the host level loop grows the trees (reason `scratch_too_large`). The reasons `depth_gt_12` and `memory_gate` are gone. Default plan
  against master, RTX 5090, 1000 rounds: covtype 8191/13 1.137x, higgs 16383/14 1.207x and 131071/17 1.194x (from the
  prefix flow); epsilon 2048/11 under a 2 GB memory cap 1.142x (pair chunks instead of the prefix); the complete tree's
  select also writes its descriptors in wide stores, so shapes already on it gain too (higgs 4096/12 1.127x, covtype
  2048/11 1.061x, covtype deep 1.040x, epsilon fixedpoint 0.998x). Model outputs are unchanged (bit-identical models).
- **Selective trees stay on the device until their first binding level** (FULL_DEVICE_PLAN P7). A binding leaf
  budget (`2^max_depth > num_leaves + 1`) or unlimited depth trains with selective grow-then-prune growth; its device
  levels used to stop after a static `min(floor(log2(num_leaves)), max_depth - 1, 10)` levels. They now continue on
  every level where applied splits + valid leaves <= `num_leaves - 1` (where the host's greedy selection provably takes
  every candidate), tested per level, and hand the tree to the host's selective loop only at the first level where
  that fails (or finish it). The levels past `floor(log2(num_leaves))` run as a captured two-level body relaunched
  while a mapped device flag says the tree continues. `FALCATA_DEBUG=diag` prints one `device_tree: selective
  hand-off at level k (binding|complete)` line per tree instead of the `selective_budget` / `selective_unbounded`
  fallback line. The `cuda_plan` key `selective_device_prefix` is removed (accepted with a warning); `device_tree:off`
  now runs the host's selective loop on every level. Strict A/B against master `f40a1690`, RTX 5090, 1000 rounds:
  fraud 255 leaves unlimited depth 1.058x (hand-off at levels 12-36 instead of 7), higgs 4095 leaves unlimited
  depth 1.051x (level 13 instead of 10); binding budget 151/10 1.003x and unbounded 1024 leaves
  0.997x (both hand over at the old level on every tree); unchanged routes (covtype small with per-node
  sampling 1.001x, covtype deep 1.001x, epsilon fixedpoint 0.998x). Model outputs are unchanged (bit-identical
  models).
- **Complete device trees with per-node feature sampling** (#171). Trees with `feature_fraction_bynode < 1` (without
  interaction constraints) now grow as complete device trees too: each node's keyed feature sample, its mask and its
  task list are drawn by a device kernel beside each level's histogram construct, inside the tree's captured graph,
  instead of on the host per level with two uploads (`cuda_plan` key `device_bynode_masks`, default on; off restores
  the host level loop). The kernel reproduces the host's keyed draw exactly (the same generator, the same
  `Random::Sample` branch, the same task lists), so models are unchanged (bit-identical models). Measured on an RTX
  5090 against master, default plan, 1000 rounds: covtype small (7 classes, 128 leaves / depth 7) with
  `feature_fraction_bynode` 0.5 1.322x, fraud deep (1024 / 10) with 0.5 1.206x; covtype deep without per-node
  sampling 1.003x and random forest (forest slots, unchanged route) 1.005x; epsilon (512 / 9, `feature_fraction` 0.5) with 0.5
  1.485x.
- **Categorical CUDA trees no longer reallocate per split** (#170). Each categorical split grew the tree's device
  bitsets by a fresh allocation, two copies and a free (and a free synchronizes the device): about 37 allocations and
  37 frees per tree on a 32-leaf multiclass categorical cell. The categorical split record now lives in buffers the
  tree learner keeps across trees, presized to the per-tree bound and grown by doubling, and each tree keeps only
  exact-size copies of what prediction reads (about 3 allocations and 4 frees per tree remain, none per split). Master
  vs this change, RTX 5090: categorical 32/5 multiclass 1.177x (0.816 -> 0.693 ms/tree), airline with three
  categorical columns, 1023 leaves/depth 10, 1.092x (49.1 -> 44.9 ms/tree); covtype deep (no categorical features)
  unchanged (1.000x). Model outputs are unchanged (bit-identical models).
- **Selective growth starts on the device** (#172). A binding leaf budget
  (`2^max_depth > num_leaves + 1`) or unlimited depth (`max_depth = -1`) trains with selective grow-then-prune growth,
  which read every level back twice. Its first K = `min(floor(log2(num_leaves)), max_depth - 1, 10)` levels (when
  K >= 2), on which it provably splits every valid leaf, now run as the graph-captured `device_levels` prefix; the
  host's selective loop
  continues from the prefix's journal (`cuda_plan` key `selective_device_prefix`, default on; removed again later in 1.2 by
  the dynamic selective levels above, so it never ships). Same eligibility as the
  prefix (quantized, numerical, scalar, single GPU, `feature_fraction_bynode` 1.0). Strict A/B against master
  `fe163428`, RTX 5090, 1000 rounds: binding budget 151/10 1.089x, unbounded 1024 leaves 1.064x, higgs 255/10 1.042x,
  fraud 255 unlimited 1.049x; complete-device-tree cells unchanged (covtype deep 0.997x, epsilon fixedpoint 0.999x).
  Model outputs are unchanged (bit-identical models).
- **The selective prefix is trimmed**. The device levels that start selective growth (see above) no longer record
  a device tree that selective growth never reads. The select that runs at the end of each level's best-split sync
  kernel is several microseconds shorter per level (for the plain `device_levels` prefix too). The hand-off to the host loop copies each journaled split record
  once. The partition launch takes the complete device tree's joint worker bound. No new `cuda_plan` keys (part of
  `selective_device_prefix`, itself removed later in 1.2). Strict A/B against master `5bec2574`, RTX 5090, 1000 rounds:
  - binding budget 151/10: 1.034x;
  - unbounded 1024 leaves: 1.035x;
  - higgs 255/10: 1.027x;
  - fraud 255 unlimited: 1.025x;
  - complete-device-tree cells unchanged (covtype deep 1.002x, epsilon fixedpoint 1.001x).

  Model outputs are unchanged (bit-identical models).

- **Random-forest groups of one tree take the device flows** (#173). Under `forest_batched` a group of one tree
  (`forest_group:1`, a binary or regression forest whose automatic group size settles at one round, the last group of
  a `forest_group:N` training, every round of a binary or regression forest under fixedpoint error feedback) now trains on the booster's learner as sequential
  training does instead of as a forest slot: no other slot thread runs beside it, so it takes the complete device
  tree (with device per-node masks) and the `device_levels` and selective device prefixes (and, before #177, the
  quantized graph prefix under `graph_quant:on`). Groups of two or more trees (every multiclass round) keep slot mode (`cuda_plan` key
  `forest_single_job_device`, default on; `FALCATA_DEBUG=diag` names each group's mode). RTX 5090, master vs this
  change: rf-control (binary, depth 7, `feature_fraction_bynode` 0.5) 1.243x, without per-node sampling 1.064x;
  multiclass and non-quantized forests and gbdt unchanged (0.988-1.002x, noise). Model outputs are unchanged
  (bit-identical models).
- **Categorical CUDA trees record a level at once** (#174). The level loop read each level's categorical bitset
  lengths back and then recorded every categorical split with its own launch and two blocking copies. One kernel now
  records all of a level's categorical splits and appends their bitsets at offsets summed on the device, and the tree
  end reads the whole categorical record back with one copy (`cuda_plan` key `cat_level_record`, default on). Master vs
  this change, RTX 5090, 1000 rounds: categorical 32/5 multiclass 1.170x (0.695 -> 0.594 ms/tree), the same at 255
  leaves/depth 8 1.177x, airline with three categorical columns, 1023 leaves/depth 10, 1.058x (45.2 -> 42.7 ms/tree);
  covtype deep (no categorical features) unchanged (1.004x). Model outputs are unchanged (bit-identical models). Also
  fixes CUDA training on a categorical feature whose largest category value is a positive multiple of 32: its bitset
  was sized one word short (a largest value of 64 failed with an invalid-argument CUDA copy).

- **Why a tree is not a complete device tree, and opt-in routing keys removed** (#177). Under `FALCATA_DEBUG=diag`
  every CUDA tree the complete device tree did not grow is reported as `device_tree: fallback (<reason>)
  route=<route>`, once per route change, with a stable reason vocabulary (`selective_budget`,
  `categorical`, `monotone`, ...; listed in `docs/performance.md` and
  `include/Falcata/cuda/cuda_device_tree_reason.hpp`); it replaces the `device_tree: fallback to the prefix/host flow`
  and `device_tree: host fallback` lines. Removed, with the flows only they reached: the `cuda_plan` keys
  `batch_kernels`, `batch_apply`, `selective`, `batch_wide`, `cat_hybrid`, `apply_struct_fused`, `gap_copy_fused`
  and `graph_quant` (the opt-in quantized captured graph prefix), the `FALCATA_DEBUG` tokens `syncpairs`, `maxsplits=N`
  and `aggressive`, and the `FALCATA_SINGLE_STREAM` switch (and later in 1.2 `graph_loop`, `graph_det` and
  `selective_device_prefix`, see below). Old plan strings that name a removed key are accepted with a warning and now
  train the default model. Default-plan model outputs are unchanged (bit-identical models).
- **Non-quantized trees grow as complete device trees; the non-quantized graph loop is removed** (#180).
  Depth-limited `quant_mode=none` trees with `max_depth <= 11` and `num_leaves <= 2047` (single GPU, scalar,
  numerical, no per-node masks), which the CUDA-graph level loop (L1.5) grew, now take the complete device tree: its
  levels construct in 64-bit fixed point (under `nonquant_deterministic`, which is opt-in since #636, see Model
  changes) and run the non-quantized fix/subtract and level find on the device's live pairs, the graph loop's kernels,
  so with the key models are unchanged (bit-identical models) and run-to-run deterministic. The
  graph loop, its device controller and the `cuda_plan` keys `graph_loop` and `graph_det` are removed (old strings are
  accepted with a warning; `graph_loop:off`'s one-sync flow is now `device_tree:off`). Other non-quantized shapes keep
  the one-sync host flows. Strict A/B against master, RTX 5090, 1000 rounds: nonquantized control (128 / 7) 1.406x,
  fraud deep non-quantized (1024 / 10) 1.470x, higgs non-quantized (1023 / 10) 1.845x; quantized covtype deep and
  epsilon fixedpoint unchanged (0.999x each, walls overlapping).
- **Complete device trees with L1, path smoothing and two leaves; no root tail** (#182). Quantized trees with
  `lambda_l1` or `path_smooth` grow as complete device trees: the level split finder now has the per-pair search's
  L1 / smoothing instantiations (each block runs the per-pair kernel's own inner search), where these configurations
  took the host two-sync loop's per-pair search before. Quantized two-leaf trees (`num_leaves=2`, any `max_depth`) are
  the complete device tree at depth 1 (before: the per-split loop). The device tree's root tail is removed: a
  split-less level root used to be searched again with the classic per-leaf search, which since the per-tree feature
  sample is translated to bin-matrix columns finds no split either. Models are unchanged (bit-identical models).
  Non-quantized L1 / smoothing trees and stumps, and L1 / smoothing with per-node feature sampling, keep their routes
  (moving them would change their models). The `device_tree: fallback` reasons `compact_16bit`, `large_bin_layout`
  and `root_tail_parity` are removed (the first two named configurations that a feature of more than 256 bins already
  refuses). Strict A/B against master, RTX 5090, 1000 rounds: fraud deep with `lambda_l1` 2.648x, covtype small with
  `path_smooth` 3.489x, fraud medium with `num_leaves=2` 1.506x; covtype deep, epsilon fixedpoint and the unchanged
  routes 0.999x to 1.004x.

- **Categorical datasets grow as complete device trees; the per-split categorical record is removed** (#186).
  Quantized, depth-limited trees with categorical features (`2^max_depth <= num_leaves + 1`, single GPU,
  scalar), which the host level loop grew with two readbacks per level, now take the complete device tree:
  its select lists each level's categorical splits, one kernel builds their bitsets and the apply's default
  directions, and the tree records the level on the device at offsets summed there (#174's level record), inside the
  tree's captured graph; the record buffers are sized for the tree's worst case before it starts, so nothing grows
  or is read back while the tree grows; categorical trees also take the lean tree end with its inline final-level
  leaf map. Models are unchanged (bit-identical models). The presized record counts as
  fixed scratch of the device tree's memory plan (#181's pair chunks: a record that leaves no room for one pair's
  search, at very high category values, keeps the host level loop with reason `scratch_too_large`); `quant_mode=none`
  keeps the host flow (reason `categorical`). The `cuda_plan` key `cat_level_record` is removed with the per-split record loop it switched back
  to (old strings are accepted with a warning); vector-leaf trees record categorical levels the same way. Strict A/B
  against master, RTX 5090, 1000 rounds: categorical 32/5 multiclass 1.138x (0.607 -> 0.533 ms/tree), the same at
  255 leaves/depth 8 1.152x, airline with three categorical columns (1023/10, kernel-bound) 0.998x; categorical
  unbounded (selective, unchanged route) 1.000x, covtype deep 0.999x and epsilon fixedpoint 0.999x (no categorical
  features).

- **Developer diagnostic: the device greedy selection in shadow mode** (#187). `FALCATA_DEBUG=r3shadow` runs a
  device port of the selective loop's greedy leaf-wise selection beside the host's on every level, compares the two
  and prints one `r3_shadow:` timing line per level, a mismatch summary per tree and `r3_shadow: MISMATCH` lines
  (docs/performance.md). It changes no model and no route, and costs nothing without the token. The shadow found no
  mismatch on 5,552 levels of four real cells. Its one-thread kernel is 6-18x slower per level than the host round
  trip it would replace, so the device route waits for a parallel selection.

- **Developer diagnostic: a parallel device greedy selection in shadow mode** (#188). `FALCATA_DEBUG=r3shadow=par`
  (or `r3shadow=both`) runs a parallel version of the selection beside the host's. It keeps each level's order on the
  device and merges the next frontier into it, resolving exact gain ties with the host's tie-break. On the four cells
  it matched the host on every level. Its median kernel time per binding level was 0.23-0.69x of the host round
  trip; that excludes launch latency and the apply work a device route adds, and budget's and fewbin's tails are close
  to or above it. It changes no model or route.

- **8-bit split columns read straight from the rows under feature sampling** (#613, #626). With `max_bin` above 16,
  feature-sampled CUDA trees skip the per-tree column copy (3.5x on a 2,568-column multiclass fit). Trees over every
  column keep the copy, which is made once for the whole run (higgs deep trees had become 1.5x slower with the strided
  read). A feature-sampled tree also keeps the copy where it moves fewer bytes than the strided read
  (`split_packed_read8_cost`, #637): deep trees over narrow rows that do not fit in the L2 cache (higgs at
  `feature_fraction` 0.9 had become 1.36x slower). Bit-identical models.

- **Less host memory for the streaming device builder's bin sample** (#615). `FLC_DatasetDeviceBuilder*` (and so a
  Dataset from a list of CUDA arrays, and `FLC_DatasetCreateFromMatsDevice`) expanded the bin-construction sample into
  per-column value and row-id arrays for all columns at once, about 18 bytes of host memory per sampled cell. It now
  keeps the sampled cells as they are (4 bytes per float32 cell) and expands one column at a time while the bin
  mappers are found. Feature bundling keeps the row sets of features with at least one row per 64 sampled rows as
  bitmaps instead of index arrays (sparser sets stay arrays). A 200,000 x 3,000 float32 build grows the host peak by
  2.7 GiB instead of 10.2 GiB, and its construct is about 25% faster. Datasets and models are unchanged
  (bit-identical).

## Model changes

- **Non-quantized CUDA training uses a histogram cost rule** (#636).
  With `quant_mode=none`, `nonquant_hist_cost` selects fixed point or float
  atomics using the training shape and histogram precision. Float atomics can
  use fp32 histogram storage on supported data and can give different model
  bits on repeated runs. Request run-to-run identity with
  `deterministic=true` on training that stays non-quantized, or with
  `cuda_plan="auto,nonquant_deterministic:on"`. An explicit plan key takes
  precedence over `deterministic`. When `deterministic=true` selects quantized
  training, it uses `quant_mode=fixedpoint`. Quantized training sums integer
  histograms and retains run-to-run identity. In 1.1 `nonquant_deterministic`
  was on by default. Where the rule selects fixed point, training gives the
  model that `nonquant_deterministic:on` gives. Where the rule selects float
  atomics, the model changes in the last bits. On 13 benchmark shapes at fp64 and fp32 on an RTX 5090, the
  rule took float atomics on 8 of 26 cells, at 0.80 to 0.95 of the 1.2 master
  round time (epsilon deep fp32 0.80, fraud deep fp32 0.88, year deep fp32
  0.88). The other 18 cells trained master's model bit for bit at the same
  speed within noise (docs/performance.md section 10v). The rule's thresholds
  were measured on that one GPU. On other GPUs it can pick the slower
  construct for a shape, which costs speed but never correctness.
  `cuda_plan="auto,nonquant_hist_cost:off"` forces float atomics, and
  `cuda_plan="auto,nonquant_deterministic:on"` forces fixed point.

- **Exact feature bundles** (#623, #624). Exclusive feature bundling stored some training rows of bundled columns in
  the wrong bin, so training counted them on one side of a split while their values (and prediction) put them on the
  other. A bundle kept up to `total_sample_cnt / 10000` sampled rows on which two of its columns are both off their
  most frequent bin (LightGBM's tolerance; such a row keeps only the last column's bin), and `BinMapper::FindBin` sorted
  the sampled values in place, so the bundle search paired the value of one row with the id of another and checked the
  wrong rows for conflicts wherever a column's most frequent bin is not the zero bin (mostly 0.5, mostly 1, NaN). Bundles
  are now conflict-free on the sampled rows and `FindBin` leaves its input unchanged. Models trained with bundling change
  slightly where the bundles change: a production-shaped 16-class fit (124,609 x 222, 0/1 columns) had 2,501 row-visits
  on the wrong side of a split in 300 iterations and has none; a 67,753 x 6,460 fit went from 1,007 to none (5,852 to
  6,041 groups). Datasets without sparse or 0/1 columns are unchanged. Binary datasets saved earlier keep their old
  bundles, misplaced rows included, until they are rebuilt from the raw data. Exclusivity
  is still proven on the bin sample only: when a dataset has more rows than `bin_construct_sample_cnt` and columns share
  a bundle, construction says so in a warning (#634 tracks the fix).

- **No floating-point contraction in the CMake build** (#616). GCC and Clang fuse `a * b + c` into one FMA instruction
  whenever the target ISA has FMA, so the same data trained different models depending on the compiler's default ISA.
  The CMake build now passes `-ffp-contract=off` to GCC/Clang (and to nvcc's host compiler). Builds whose ISA has no
  FMA (default x86-64) are unchanged. Builds where FMA is in the base ISA or the compiler's default (aarch64, Apple
  silicon, `-march=native` or x86-64-v3 toolchains such as GCC 15 on Ubuntu 26.04) train slightly different models
  than 1.1 at the last-bits level, and now the same models as x86-64. Explicit FMA intrinsics (Eigen, used by linear
  trees) are unaffected; the R package's own build (Makevars) does not use the flag.

- **Linear-tree coefficients are run-to-run deterministic on CUDA.** The per-leaf normal equations of a
  `linear_tree` fit (X^T H X and X^T g) were summed with one double `atomicAdd` per row and entry, so `leaf_const` and
  `leaf_coeff` moved at the 1e-12 relative level from run to run on every CUDA flow and with every knob
  (`deterministic` included). They are now a fixed-order reduction over each leaf's rows in partition order: chunk sums
  in a fixed thread order, then the chunk sums in chunk order. Linear-tree models on CUDA change once, at that
  1e-12 level (tree structure and leaf values unchanged), and then repeat bit for bit wherever the trees do (quantized
  training, or non-quantized with `nonquant_deterministic`, see Model changes); the complete device tree and
  `device_tree:off` now give the same linear model. CPU parity stays inexact (the CPU learner sums in another
  order). The reduction is also faster than the contended atomics: strict A/B against master, RTX 5090, 1M rows,
  1000 rounds: 31 leaves unbounded 2.02x, 63 leaves / depth 6 4.49x, 50 features with deep leaves 1.60x; non-linear
  covtype deep unchanged (1.003x, same model).

## Fixes

- **CUDA lambdarank handles a query with no documents** (#627). It no longer crashes on a query with zero documents.
- **Positions in the CUDA wheel** (#627). The CUDA wheel accepts `position=` data, and position-aware ranking trains
  with `device_type=cpu`. On `device_type=cuda`, lambdarank and rank_xendcg with positions now fail when the Booster
  is created, with a message pointing to `device_type=cpu`; before, the failure came when the Dataset was built. When
  `device_type` is unset and a GPU is present, the device resolves to CUDA, so pass `device_type=cpu` yourself.
  Positions loaded from a `.position` file were never refused before and were silently ignored on CUDA; they now get
  the same error. Non-ranking objectives now accept and ignore positions in CUDA builds, as CPU builds already did.
- **Linear trees on a Dataset without raw values** (#628). `linear_tree=true` on a Dataset built without raw values
  now gives a clear error on CUDA instead of a segfault.
- **CUDA training on a subset of a Dataset already on the device** (#629). Such a subset is made by `cv()` with
  `init_model`, by `cv()` or `Dataset.subset()` after training on the same Dataset, and by the C API
  `FLC_DatasetGetSubset`. Training on such a subset with CUDA crashed with a segmentation fault: in 1.1 with
  `max_bin <= 15`, and on the 1.2 development line (since #613) at any `max_bin`. This is fixed. In 1.1, such subsets
  with sparse-encoded columns and `feature_fraction < 1` could also build wrong splits (found by reading the code, not
  reproduced); sparse-encoded columns reach CUDA only from Datasets built outside CUDA, so that exposure is narrow.

## Documentation

- **`num_gpu` states the multi-GPU requirements**: NCCL loaded at runtime (`falcata[multigpu]`, an NCCL 2.x wheel such as `nvidia-nccl-cu13`, or a system `libnccl.so.2`; without it training falls back to one GPU), the depth-limited configuration quantized multi-GPU needs (at least `2^max_depth <= num_leaves + 1`), host-staged transport (for data that does not fit one card, not for speed) and how multi-GPU models differ from single-GPU ones. Both NCCL wheels verified with falcata 1.1.0 on 2x RTX A4000, driver 580.
