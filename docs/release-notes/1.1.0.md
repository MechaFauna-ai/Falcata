Falcata 1.1 makes quantized CUDA training faster on wide and low-cardinality data,
makes non-quantized CUDA training deterministic by default, moves random forests onto
the device, and removes three mechanisms that did not pay for themselves. Several
fixes change model outputs; read [Models that change](#models-that-change) before
upgrading a pipeline that compares models byte for byte.

## Features and performance

- **Quantized CUDA training.** Tiled column-major fill of each tree's sampled columns;
  pair-joint histograms with five-bit code words, one thread per word; a mixed-radix
  six-bit view so features with a missing state keep the code-word path (#109); occupancy
  and launch scheduling work; programmatic dependent launches on the level chain (#117);
  warp split-finder tiers and few-bin finder paths (#97, #111); bagged and sparse-ish data
  on the batched level kernels (#99, #101). See the
  [release article](https://github.com/MechaFauna-ai/Falcata/blob/master/docs/blog/falcata-1.1.md)
  for measured effects. Measured on `1408ee79` against the 12 October master
  `a65d34e8` (unreleased; after 1.0.5), the fifteen article workloads train
  1.189× (stochastic) and 1.202× (fixed point, without fraud deep,
  which stops early; all fifteen rows 1.216×, without both fixed-point fraud rows
  1.195×) faster by geometric mean; Numerai deep at 30,000 rounds takes
  105.82 s instead of 112.97 s.
- **Deterministic non-quantized training** (#122). `quant_mode=none` on CUDA builds level
  histograms with a 64-bit fixed-point accumulator and produces the same model on every
  run. Plan key `nonquant_deterministic` (default on).
- **Random forests on the device** (#103, #113, #115, #116, #121). Device objective and
  lazy training score; per-node feature masks in the level-batched flows; a forest's trees
  grown together; exact count histograms for non-quantized forests.
- **Fewer host round trips** (#123). Eligible quantized trees enqueue their first
  `min(floor(log2(num_leaves)), max_depth - 1, 10)` levels without per-level readbacks.
- **Opt-in whole device trees** (#130, #142, #144). `cuda_plan="auto,device_levels:off,device_tree:on"`
  grows eligible depth-bounded quantized trees on the device with one growth readback.
  Off by default. Automatic controller selection is still under validation and is not
  part of this release.
- **Static compact-view rule** (#112, #114) replaces the timed view probe.
- **Classification stability** (#91, #93).
  `max_delta_step=-1` (automatic) bounds non-quantized classification leaf steps;
  CPU splits check the actual partition before committing. On `1408ee79`,
  66 of 66 FP64 CUDA and 74
  of 74 CPU stability cases pass all gates.

## Fixes

- CUDA `rank_xendcg` crashed on queries of 65,536 or more items (#131).
- Non-quantized CUDA columns with more than 6,144 bins corrupted the previous histogram
  partition (#132).
- CUDA categorical `extra_trees` drew its threshold on every thread and varied run to
  run (#135).
- Quantized CUDA root statistics lost low Hessian bits: the packed 64-bit root total
  (gradient sum << 32 | Hessian sum) passed through a double, which is inexact once the
  integer gradient sum reaches 2^21 (#146).
- Whole device trees recorded a stump where the host would split the root (#153).
- CUDA constructs sampled the wrong columns on bundled (EFB) data with
  `feature_fraction < 1` (#154). The same PR clears the level-wise root histogram before
  the classic root search, which had counted the root twice when the batched root found
  no split.
- Quantized sparse rows wider than 504 elements dropped elements (#102).
- Quantized CUDA training ignored `feature_fraction_bynode < 1` and interaction
  constraints (#107).
- CUDA weighted L1/quantile initialization used wrong prefix sums (#124).
- Metrics with host objectives on CUDA (GOSS, cross_entropy, tweedie, gamma) were wrong
  (#105); objective resets now rebuild metrics (#108).
- Multi-GPU NCCL split rows over all devices instead of the training ranks (#106).
- One-sync prefix ordering (#95); linear-tree storage across resets (#149); Dataset
  ownership during training-data replacement (#150).

## Removals

- **Construct JIT** (`construct_jit`) and the `libnvrtc` runtime dependency (#110). The
  `nvidia-cuda-nvrtc-cu12` pip dependency is gone.
- **Runtime tuner** (`tuner`, `tuner_explicit`, `view_probe_lo`, `view_probe_hi`), the
  view probe and the wisdom file under `~/.cache/falcata/` (#114).
- **Host quantized training** on CPU and OpenCL, which validation already rejected (#148).
- Unused CUDA state and eager metadata uploads (#147).

## Models that change

Compared with 1.0.5, these change some model outputs:

- **#122:** CUDA `quant_mode=none` with depth-limited trees, `feature_fraction < 1` or wide
  levels, and `cuda_precision=fp32`. Previously a different model per run;
  `nonquant_deterministic:off` restores the float atomics. All thirteen non-quantized
  benchmark workloads therefore change; the release candidate gives one model per
  workload in 13 of 13.
- **#146:** CUDA fixed-point runs whose integer root gradient sum reaches 2^21 (strong
  class imbalance under the outlier-robust scale). Of the 30 quantized benchmark
  comparisons, only fraud shallow and deep in fixed point changed (28 of 30
  byte-identical; bisected): shallow with #146 alone,
  deep with #146 and then #154, after which it stops at 357 of 500 trees. One leaf's
  Hessian sum differs in the seventh digit from the second (deep) or third (shallow) tree
  on. The fraud gradient sum is about 7.27 million at the first iteration (estimated by
  hand, not measured). Held-out AUC
  0.9780 → 0.9774 (deep),
  0.9790 → 0.9808 (shallow). Every other
  quantized classic and Numerai benchmark model is byte-identical to `a65d34e8`'s
  (28 of 30).
- **#154:** CUDA training on data with bundled features (for example one-hot blocks) and
  `feature_fraction < 1`, for every plan; and quantized runs where a level-wise root finds
  no split (the root histogram is now cleared before the classic root search, which had
  counted the root twice and could still split).
- **#135:** CUDA `extra_trees=true` with more categories than `max_cat_to_onehot`; the
  result is the most common of the former run-to-run models.
- **#91:** non-quantized binary, softmax and one-vs-all classification (automatic step
  limit; `max_delta_step=0` restores unbounded updates).
- Corrections of wrong output: #102, #107, #113 (per-node samples now drawn per node;
  `level_bynode_masks:off` restores shared-stream sampling), #121 (non-quantized forests
  deeper than 12 levels or with sampled features), #124, #132.

## Upgrade notes

- Plan strings naming removed keys log `cuda_plan key <key> was removed` and train the
  default plan. Nothing is written under `$HOME` any more; an old
  `~/.cache/falcata/wisdom.txt` can be deleted.
- Raw C++ configurations that request host quantized training are rejected.
- `deterministic=true` documentation now describes the CUDA defaults and the modes that
  stay nondeterministic: linear trees, ranking objectives, multi-GPU training,
  non-quantized vector leaves and `nonquant_deterministic:off`.

## Known limitations

Non-quantized CUDA training is deterministic but not faster: against `a65d34e8` it runs
at 1.006× by geometric mean, and four of the six deep shapes are slower (Higgs
0.889×, Epsilon 0.890×, Year
0.929×, Airline 0.944×); #122 alone cost
0.96–1.08×; Higgs deep's 0.889× is outside that, and the cause is not isolated. On the release article's shapes it remains
1.04–2.1× slower than the unmerged PR #71 prototype's October timings in its
[immutable report](https://github.com/MechaFauna-ai/Falcata/blob/523ed775ad2eec9eeca147c4815c39a8f9400f70/docs/2026-10-09_noquant-timings.md)
(measured 16 October on `a65d34e8`), and those scan speedups still need porting onto
the deterministic construct. The 16,384-leaf FP32
six-state recipe still exceeds the compact view's memory admission and takes the
full-width mask view (5.983×
the five-state training time). The device-driven level prefix
(#123) falls back to the host path for later trees when its graph captures keep missing
under layout churn, and its benefit is selective (0.98–1.05× per test cell). The
verification lattice has no cell for bundled (EFB) data with `feature_fraction < 1`, the
case #154 fixed; that coverage is added with the next reference regeneration.
